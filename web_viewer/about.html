High-speed lightning capture and analysis
Developed by Karl Stock in Flagstaff, Arizona

What It Does

  • Pi Lightning Video Capture is a high-speed video capture and analysis system designed to detect, record, and analyze lightning events.
  • A Raspberry Pi with a high-speed camera continuously monitors the scene at 260 FPS, and preserves 2 second video clips when a possible lightning event triggers capture.
  • Each capture is stored as an MP4 video together with a JSON sidecar containing trigger information, camera metadata, configuration, and per-frame measurements.
  • The system is designed for unattended operation where continuously storing the entire high-speed camera stream would produce far too much data.
  • The system can be deployed in the field without the need for an internet connection.
  • The web-based controller allows sensitivity to be adjusted. Fixed-site cameras might use Medium or Low sensitivity, while field systems actively monitoring storms can use High sensitivity.

Two-Stage Analysis

Candidate detection  →  Solution filtering
  • The central design separates fast real-time detection from careful post-capture classification.
  • Stage 1 — Candidate detection: while frames are arriving, CandidateFinder performs lightweight measurements such as mean brightness, adjacent-frame brightness change, and the fraction of pixels that changed significantly.
  • A Candidate is a saved clip that might contain lightning. It is not a claim that a flash occurred. The first stage is intentionally biased toward preserving questionable events rather than risking the loss of a real lightning flash.
  • Stage 2 — Solution filtering: after the Candidate has been safely recorded, SolutionFilter examines the broader frame sequence, including behavior before and after the trigger.
  • A Solution is a Candidate that survives the second-stage rejection filters and is therefore classified as a likely true lightning flash.
  • The design principle is simple: capture first, analyze later.

Heuristic Filtering — No Machine Learning

  • The current SolutionFilter uses explicit, inspectable heuristics. It does not use a trained machine-learning model.
  • The filtering logic looks for temporal and brightness patterns characteristic of known false positives, including sustained brightness noise, frame-dropout anomalies, steady-state brightness changes, stair-step behavior, and other repeatable artifacts.
  • Because the rules are explicit, a classification can be tied directly to measured frame behavior and a specific rejection reason.
  • The smoke-test collection is used as a regression suite. When a new false-positive pattern is found, the filtering heuristics can be refined.

Current Test Results

  • The current SolutionFilter smoke-test suite contains 35 captures: 18 true lightning flashes and 17 anomalies.
  • With the current filter configuration, all 35 captures are classified correctly.
  • For this suite, recall, precision, and accuracy are each 100.0%.

Using the Viewer

  • Select a capture from the published list to open the browser-based frame viewer.
  • Step through the video one frame at a time or in ten-frame increments while comparing the image with the brightness graphs.
  • Graph markers show the original Raspberry Pi trigger, the replay trigger, and the currently displayed frame.
  • High, Medium, and Low sensitivity selections expose the stored Candidate and Solution results for each sensitivity level.
  • The Solution panel shows both the classification and the reason produced by the filtering logic.
